## Build environment

- **Node.js was not installed system-wide** (the brief expected Node 24). An official Node v24.19.0 binary, signed by the OpenJS Foundation, was already on the laptop inside the Codex runtime cache (`~/.cache/codex-runtimes/.../node.exe`). It was copied into `tasuki-cards/.tools/node/`. npm 11.21.0 was downloaded from registry.npmjs.org (sha512 integrity verified) into `tasuki-cards/.tools/npm/`. Nothing was installed system-wide and nothing was added to PATH; `.tools/` is git-ignored. In Git Bash, `source .tools/env.sh` puts both on PATH for that shell. After installing Node 24 LTS normally, `npm install` and `npm run build:single` work without `.tools`.
- **Pinned dependency versions**, each published at least two weeks before the build (exact versions in `package.json`). **Vite 7.3.7, not Vite 8**: Vite 8 bundles with Rolldown, while `vite-plugin-singlefile` 2.3.3 needs Rollup 4, and the single-file HTML is a hard deliverable. TypeScript 5.9.3 (most widely compatible), React 19.3.0, Dexie 4.4.6, Vitest 5.0.3.
- npm 11's new install-script gate skipped esbuild's `postinstall` (a binary self-check only). The platform binary `@esbuild/win32-x64` installs as an optional dependency and was verified to work.

- **Commit:** `4aac6737cb9f216c90a0a610355667cd3d921c61` (committed 2025-07-27, "Updated AgeGrade.1mi file for RunScore").
- **Files:** `2025 Files/MaleRoadStd2025.xlsx` (sheet `AgeStdSec`, "Version 2025-07-27") and `2025 Files/FemaleRoadStd2025.xlsx` (sheet `AgeStanSec`). These are the most recent road standard tables (2025, approved by USATF MLDR on 2025-01-10).

- Interpolation follows the spec, not the source spreadsheet's internal method: log(time) against log(distance) between adjacent table distances; extrapolation below 1 mile along the 1 mile–5 km slope (so the 1.30 km Campus Circuit is extrapolated, e.g. M25 standard ≈ 180.4 s); linear in decimal age between single-year rows; ages below 5 use age 5.

## Data model (spec 2)

- The spec's `Event` type is called `TasukiEvent` in code, to avoid clashing with the browser's built-in `Event` type.
- `Performance` has an optional `courseId` (and an optional `terrainFactor` override). Quick Entry picks a course directly, and a stat such as SPD needs to know which course a Circuit result was run on. Resolution order: performance course, then the event's course.
- **Deleting a performance is a soft delete** (`deleted: true` plus a history entry with the reason). It is ignored by every calculation but kept, because the spec says corrections are never destructive.
- **Circuit participation is derived** from Circuit performances, not stored, so correcting or deleting a Circuit result can never leave a stale participation record. Only `saturday_run` and `freeze` participation is stored.
- `Athlete.yearGroupYear` (optional) records which academic year the year group refers to. Age estimates for results from earlier years then use the age the athlete had at the time. If absent, the academic year of the as-of date is used.
- Every record created by "Load demo data" carries `demo: true`, so "Clear all demo data" removes exactly those records and nothing imported.
- Outsiders (non-roster competitors in pasted results) are never stored. Only the field size and each category winner's time (no name) are kept on the event.
- `displayMode: 'first_initial'` shows "Aiko T."; `'alias'` shows the public alias, or the first-initial form if no alias is set.

## Scoring (spec 3)

- **Months old (freshness, spec 3.7)** means whole calendar months elapsed (a result from 15 Jan is 6 months old on 15 Jul). Ratings step down once a month rather than drifting daily, which is easier to explain to students.
- Course records and year bands use the athlete's year group **at the time of the run**, which is the recorded year group shifted by the number of academic years.
- **Which stat a result feeds is decided by the result's kind**: circuit → SPD, climb → CLB, descent → DSC, nav → NAV, bleep → END, arm → ARM. Race, relay leg and parkrun → RACE, plus END when the effective distance is ≥ 5 km; a long run feeds END only. The course supplies distance, climb, terrain and benchmark mode. So a hill race on a climb course stays a race and does not feed CLB.
- **Only verified, non-deleted results count**, for every stat. The spec says "verified" for RACE, END and the NAV reference; this extends it to all stats, so a student-reported result never moves a rating until the coach ticks it. Every result still appears in the Career Vault with the reason it does not count ("unverified", "not a clean run", "set this course's benchmark in Settings", …). Results dated after the as-of date are ignored, so as-of views are reproducible.
- **Fixed-benchmark courses** (3.6): with no benchmark for the athlete's sex, the stat is locked with exactly "set this course's benchmark in Settings". A descent with no course at all is unscored ("no course set"), because there is nowhere to set a benchmark. Fixed scores are provisional only if the age-grade table is. The reference distance (5 km) and age (25) are config values.
- **Growth Shield** (3.8) applies to the six OVR stats, not to RACE. RACE is a weighted blend of up to three races, and lifting it to one race's peak would distort it. When the shield lifts a stat, the card shows the date of the peak result behind it. "Last 12 months" means fewer than 12 whole months old.
- **ARM has no freshness decay**: the 12-month best-level window replaces it, since 3.9 says ARM never falls on a bad retest. A domain measured below level 1 counts as level 0 ("measured"), and ARM is then clamped to 40–99. A single ARM test gets its own score only if it measured all three domains, but partial tests still count towards each domain's best level.
- **NAV**: a blank error count means 0 errors. The reference pace is the best-ever verified Circuit pace (time ÷ effective distance) up to the as-of date, including results too old to count, because the spec says "best-ever" and "a PB". With no Circuit, the best verified race, relay leg or parkrun of 5 km effective distance or less is used. The 0.5 efficiency floor is a config value.
- **Rounding**: every 40–99 score rounds half up, with float noise removed first (69.49999999 → 70).
- **Ties** between best results: highest FreshScore, then the higher unpenalised score, then the most recent. For END, an exact tie between bleep and long run goes to the bleep. The END label uses the raw distance ("from 10 km, 12 Aug").
- **Bleep**: above P95 the percentile is reported as 95, and the rating rises linearly from 96 at L_P95 to 99 at 1.2 × L_P95. Under-11s use the age-11 row and 18+ the age-18 row, as the spec says.
- **Lock hints** (≤ 3 words on the card) say why a stat is locked, most actionable reason first: "Benchmark not set", "Run the Circuit" (also used for NAV with no reference pace), "Clean descent run", a result waiting to be verified, a last result over 24 months old, or the default ("Bleep or 5K+", "Run a climb", "Complete a nav", "Test all three" / "Test calf", "Race to unlock").
- **Provisional marker**: shown on a stat when the result behind its displayed value rests on a provisional table or formula (bleep table, NAV, ARM thresholds, or the fallback age-grade table). Locked stats never carry it.

## Streaks, Surge, PBs, In-Form, badges, handicap (spec 3.10–3.14)

- **Streak weeks** count verified Circuit results and stored Saturday-run participation. A holiday week is always "holiday" (it neither counts nor breaks), even if the athlete ran a Circuit that week. A verified parkrun or long run in a holiday week earns the holiday-bonus flame.
- **Freezes**: one per half-term, taken in week order. A freeze on a week that already counts, or on a holiday week, does not use up the allowance. **A freeze in a week that no half-term covers is not honoured**, so half-terms must be set in Settings, and the Settings page warns about this. The current, in-progress week is never treated as missed.
- **Surge baselines** are race, parkrun or Circuit results from 1 to 90 days before the relay. The same day is excluded, and a relay leg or long run is never a baseline. Relay legs with no time or distance are left out. The sanity gate groups legs by event and effective leg distance (to 0.01 km).
- **Surge sanity gate: minimum group size (a new constant).** Taken literally, a runner alone on their leg distance is their own median, so any surge above +2.0% would be cut to exactly +0.7% and could never medal. In a one-team ekiden every leg distance is a one-runner group, so the gate would remove every Surge. The gate therefore applies only to groups with at least `surge.sanityMinLegs` legs that have a baseline (default 3, editable in Settings). This is open question 1 for the coach.
- **Raw PBs**: by course (`course:<id>`) for course runs, and by distance (`dist:5.00`) for races, parkruns and long runs without a course. Relay legs (they have Surge), NAV runs (times depend on errors and variants) and descents that were not clean runs are excluded. A run whose distance differs from its course distance (e.g. a 5.2 km long run on the 1.3 km Circuit) is filed under its distance, not the course. Equalling a best is not a PB.
- **In-Form** window: the as-of date and the six days before it (7 calendar days). A first-ever result is not In-Form, because there is nothing to beat. A card shows the raw PB first ("PB −12 s"), otherwise the score improvement ("SPD 71 → 74").
- **Parkrun distance**: a parkrun entered without a distance is taken as 5 km at entry time (`input.parkrunDefaultKm`).
- **Course records** use results up to the as-of date. On a tie the earlier holder keeps the record, and the year band is the athlete's year group at the time of the run.
- **Badges** are permanent achievements, so they use all-time data. Streak milestones come from the best streak (dated by the week it was reached), and the ARM badge shows the highest level ever reached in each domain. Distance and Mountain badges count any verified run that covered the distance or climb, including relay legs and long runs. The card's five-badge row takes the most prestigious badge of each kind first (record, Surge gold, expedition, Mountain, …), so one long streak cannot fill the row.
- **Handicap start sheet**: each PB is the all-time best verified Circuit time. Offsets round to the nearest 5 s (halves round up). Runners with no PB start in the first wave. Rows are listed in start order.

## Input: time parsing and name matching (spec 3.1, 4.2)

- **A time column vs free text.** In a time column, `16.15` reads as 16:15 (with a warning). In free text a dotted number may be a distance, so it is not read as a time. `16.5` is rejected as ambiguous (16:05? 16:30?), and `16.75` because seconds must be under 60. Nothing is guessed silently: every rejection says why.
- **Excel hazards**: Excel turns a typed `16:15` into `16:15:00` (16 hours). A three-part time of 10+ hours with :00 seconds is accepted with a warning, and the pace check catches the rest.
- **Free-text guards**: numbers after `place`, `leg`, `climb`, `ankle`, `calf`, `stork`, `laps`, `errors`, `field` and year groups such as `Y9` are not times. Neither are clock times (`8:10am`), Forms timestamps or paces (`3:15/km`). A lone `m` means metres in free text unless it clearly means minutes (`16m15`).
- **Dictation**: "seven fifty five" = 7:55, minutes then seconds, as the spec says. A bare number such as "755" or "1615" is never read as a time; the error suggests "16:15". Kanji numerals (十六分十五秒) are read in a single time field but not in free text, because many Japanese names contain numeral characters.
- **Pace check**: faster than 2:30/km or slower than 12:00/km is flagged; exactly on the limit is fine. The paste review uses the effective distance, so a steep mountain race is not flagged as implausibly slow.
- **Name matching ladder**: exact stored alias → normalised (either order, any script, hiragana ≡ katakana, kanji only via a stored alias, spaces ignored for kanji and kana, punctuation dropped by timing systems tolerated) → initials ("Ken S", "H. Mockridge", "M. J. Example") → fuzzy (Jaro–Winkler ≥ 0.88, suggestions only, up to 5) → unmatched or outsider.
- **Never a confident match**: a given name or family name on its own; two athletes matching at the same level ("two athletes matched"); a stored alias that is another athlete's real name. Inactive athletes are matched only if no active athlete matches, and a warning is shown.
- **Alias learning** refuses strings that would cause trouble later: the athlete's own initials or a bare name part, and anything that already identifies another athlete.
- **Duplicate detection** (roster import) compares names in either order, including aliases, in the same academic year, so a Y9 recorded last year is caught as a duplicate of a Y10 import this year.
- Not supported, by choice: run-together initials ("MJ Smith"), honorifics ("先生", "さん"), and treating romanisation variants (Oono, Ohno, Ōno) as equal. These show as fuzzy suggestions and are learned as aliases once confirmed.
- The spec's example names in the line format (4.3) may belong to real people, so the in-app Help, tests and demo data use obviously invented names instead (Aiko Testfield, Ben Sampleton, Coach Example). The line structure is identical.

## Input screens (spec 4, milestone 2)

- **Review-table statuses**: each pasted row is *Import* (confident match), *Check* (a fuzzy suggestion, an unmatched name in line format or Forms, two athletes matched, or an implausible pace), *Skip* (missing time, duplicate row, already-saved duplicate), or *Outsider*. Only *Import* rows are saved, and only when the coach presses Approve.
- **Outsiders**: in a pasted results table (website, PDF, Excel), a name that matches nobody and has no fuzzy suggestion is an outsider by default. In line format and Forms exports every name should be on the roster, so it is *Check* instead. Outsiders are never stored. They count towards the event's field size (the larger of the row count, the highest place and any field size given), and the fastest time per category (or "Overall") is kept on the event without a name.
- **Duplicates**: a row is a duplicate of a saved result when the same athlete has a live result of the same kind on the same date within 1 s (or the same laps). It defaults to *Skip*; the coach can still tick it.
- **Alias learning** happens only when the coach confirms a match the matcher was not sure of (fuzzy, ambiguous, unmatched, or a different athlete chosen by hand). The exact spelling is stored as a new alias unless it would clash with another athlete.
- **Events**: pasted results join an existing event when the name and date match (or when the coach picked the event above the text box). Otherwise one new event per header is created on approval. Circuit, climb, descent and nav headers find their course by `course <name>`, then by the event name. If there is exactly one Circuit course, a `circuit` header uses it.
- **Forms exports are always saved unverified** (source `form`), and so are line-format rows marked `unverified`.
- **Quick Entry** has a "Saturday run (attendance only)" option that records streak participation. Its live preview derives everything with and without the draft result and lists only what changes for that athlete: stats, PBs, In-Form, tier, streak and new badges.
- **Corrections need a reason**; delete is a soft delete with a reason and can be restored. The full history (who, when, before → after, reason) shows in the correction dialog.
- **Voice dictation** uses the browser's own speech recognition (Chrome sends audio to its speech service, so it needs internet; this app stores no audio). It only types into the Paste box for review. It is hidden in browsers without the API.
- **Test runner uses one worker** (`maxWorkers: 1`). This laptop runs close to its memory commit limit (about 0.3–0.8 GB free with the usual apps open), and parallel test processes crashed with out-of-memory errors.
- For the in-app browser preview, a launch config was added at `C:\Users\finga\Documents\.claude\launch.json` (it points at the project-local Node and Vite). It is not part of the app.

## Cards, avatars, printing (spec 5, milestone 3)

- **Card layout** is sized entirely in millimetres (63 × 88 mm), so the printed card matches the screen. From top to bottom: OVR box (with n/6), tier · year, display name, the RACE banner (rating, ★ caps, best race line), the avatar on a diagonal tasuki sash, six stats in a 3 × 2 grid with the date of the result behind each one (top right of each cell), streak flame plus holiday-bonus flames, up to five badges, and the footer. Long names shrink to fit rather than being cut off.
- **Styles**: Bronze (copper), Silver (steel), Gold (gold), Icon (deep violet with gold), and In-Form (a flame-orange frame with an "IN-FORM · PB −12 s" tag, kept for the week). The design is original: a vertical card crossed by a striped sash, with no shield shapes or layouts from existing trading-card or video-game designs.
- **Avatar**: one flat-colour runner in mid-stride with anime-inspired proportions. Every athlete has the same body; only skin tone (6), hairstyle (8), hair colour (6), kit colour (academy navy/red plus six generic house colours) and an accessory (cap, headband, glasses) vary. The default comes from a hash of the athlete id. Earned extras are drawn on top: compass in hand or floating, ankle guards, armour glow, motion lines, lightning trail, contour-line wings, dust burst, the tasuki sash (plain, or gold-edged from 3 caps), a flame on the sash for a Surge medal, and a red headband with tails for an 8-week streak.
- **Print geometry**: 3 × 3 cards with 3 mm gutters for crop marks, centred on A4 (7.5 mm side margins, 13.5 mm top and bottom), so nothing falls in a printer's unprintable edge. Card sheets use a named CSS page (`@page cards`, zero margins), so board printouts keep their own margins. Provisional markers and DOB never print.
- **Automated print check** (`npm run check:print`, after `npm run build:single`): headless Chrome (the installed one, via puppeteer-core) loads demo data through the real UI, opens the print studio with every card selected, and checks that every card is 63 × 88 mm and inside its A4 sheet, that no text element overflows its box, that locked stats show no numbers, and that provisional markers are hidden in print. It then prints a real PDF and checks one A4 portrait page per sheet. The PDF and a picture of sheet 1 are saved in `test-output/`.
